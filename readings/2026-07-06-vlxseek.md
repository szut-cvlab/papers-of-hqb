## 摘要

**问题**: 现代视觉语言模型（VLM）擅长整图理解与语言推理，但细粒度感知仍困难：
- 目标在哪里、边界如何与邻近物体分开；
- 哪个实例对应语言描述；
- 图中有多少个目标、应返回哪些区域；
- 查询目标不存在时，模型应拒绝而不是幻觉出一个框。

**方案**: 把视觉定位从“让语言模型生成坐标”重构为“**区域检索 + 区域引用**（region retrieval / region reference）”。候选区域被编码为可寻址的**区域 token**（概念上 `<region0>`、`<region1>`；实际特殊 token 为 `<obj0>`、`<obj1>`），语言模型通过选择、比较、引用这些区域来输出定位结果，而不是逐位生成 `[x1,y1,x2,y2]`。

**关键设计**：
- **OPN（Omni Proposal Network）**: 类无关候选区域生成，不做类别判断。
- **HFRE（Hybrid Fine-Grained Region Encoder）**: 语义通路 + 高分辨率细节通路，把候选框编码为区域级视觉表示。
- **SimpleFP**: 为 ViT 类特征补多尺度表达，兼顾大目标与小目标。
- **区域 token 推理**: 输入 = 全局图像 token + 文本 token + 编号区域 token；输出区域编号与自然语言推理。
- **两阶段训练**: 区域-语言对齐 → 感知指令微调；1.5 增加 hard-negative 拒识训练与显式 `None` 输出。

**验证**（官方 1.5 博客，Table 1–6）：
- 通用检测：VLX-Seek 1.5-3B 在 COCO 上 **F1@IoU mean 59.1**、LVIS **57.5**、ODinW13 **52.0**；1.5-10B 分别为 58.9 / 58.2 / 50.4（Table 1）。
- REC：1.5-3B 在 RefCOCO/+/g 平均 **91.6**，1.5-10B **93.0**；PixMoCount 计数 88.1 / 89.0（Table 3）。
- 无人机视角：VisDrone F1 mean **41.9 / 42.0**；RefDrone F1 inst **73.2 / 73.2**（Table 4）。
- 物体幻觉：HumanRef FP/GT **14.1 / 12.7**，VisDrone **8.7 / 7.0**，RefDrone **18.0 / 19.6**，低于 LocateAnything-3B 的 30.7 / 28.8 / 71.3（Table 6）。

## 1. 背景与动机

**现有 VLM 的定位方式**:
- 很多 VLM 通过生成坐标 `[x1, y1, x2, y2]` 定位。坐标是长数字序列，不是自然语言，存在格式、顺序、归一化错误的风险。
- 多目标时输出长度成倍增长，解码路径变长，推理延迟高。
- 对边缘设备/具身场景，延迟与可靠性都不可接受。

**VLX-Seek 的改法**:
- 先把图中可能的前景区域提取为候选；
- 把每个候选编码成语言模型可读的区域 token；
- 模型只需输出区域编号（如 `<obj2>`、`<obj10>`），无需生成坐标数字。
- 这把定位变成 LLM 擅长的操作：比较、选择、引用、解释、推理。

**目标场景**:
- 端侧具身视觉：无人机、监控、机器人视角；
- 需要小目标、密集布局、非常规视角、长尾类别的细粒度感知；
- 需要明确拒绝不存在的目标，避免“每个查询都框一个东西”。

## 2. 方法

### 2.1 总体流程

```text
图像 + 文本查询
   ↓
OPN：生成类无关候选区域
   ↓
HFRE + SimpleFP：把每个候选编码为区域 token
   ↓
LLM：全局图像 token + 文本 token + 区域 token 联合推理
   ↓
输出区域引用（<obj*>）与自然语言答案
```

与“生成坐标”相比，定位输出被压缩为少量区域 ID，显著缩短解码长度；候选区域由外部模块给出，LLM 不需要从零回归几何。

### 2.2 候选区域生成：OPN

- OPN（Omni Proposal Network）负责召回图中可能的前景区域，不做类别判断。
- 与 VLM 主干解耦，可替换为其他检测器或人工指定 ROI。
- **重要限制**：官方 README 明确说明，受公司政策限制，**内部训练的 OPN 未开源**；仓库集成开源的 **WeDetect-Base-Uni** 作为替代候选生成器，也可通过 `--bbox-list` 传入任意检测器的框。

### 2.3 混合细粒度区域编码器：HFRE

候选框只是几何提示，本身不告诉语言模型“框里是什么”。HFRE 把每个候选区域转为区域级视觉表示，包含两条互补通路：

1. **语义通路**：保留基础 VLM 的视觉-语言对齐与高层理解能力。
2. **细节通路**：提供更高分辨率的局部细节、空间结构、边界、纹理、小目标线索。

两路特征经区域-语言连接器（region-language connector）投影到 LLM embedding 空间，使每个候选框成为一个可读、可引用的区域 token。

### 2.4 SimpleFP

- 为 ViT 类视觉特征补多尺度表达。
- 让模型同时处理大目标与小目标：深层语义强但分辨率低，浅层细节强但语义弱，多尺度融合缓解这一矛盾。
- 官方仓库中 `vlx_seek/models/vlx_seek_1_5/multimodal_visual_prompt_encoder/simple_fpn.py` 实现了 SimpleFP（注释说明其基于 ViTDet 的 SimpleFPN）。

### 2.5 区域 token 推理

- 区域 token 概念上是 `<region0>`、`<region1>`…，实际特殊 token 序列化为 `<obj0>`、`<obj1>`…。
- LLM 输入 = 全局图像 token + 文本 token + 编号区域 token。
- 模型在候选区域上做语言条件检索，输出匹配的区域 ID 与自然语言解释。
- 因为输出是区域引用，模型不需要写四位坐标，定位 token 数大幅减少，适合端侧低延迟。

### 2.6 拒绝不存在的目标

- 1.5 将输出格式从“隐式省略”改为**显式 `None`**：请求 A、B 时，如果只有 A 存在，模型输出 A，并显式把 B 标为 `None`。
- 训练时加入 **hard-negative rejection**（困难负样本），让模型学会拒绝图中不存在的目标，而不是强行给出一个框。
- 官方用 FP/GT 衡量物体幻觉：假阳性检测数 / ground-truth 目标数，越低越好。

## 3. 训练

### 3.1 两阶段训练

1. **区域-语言对齐（Region-Language Alignment）**
   - 主要冻结 VLM 主干；
   - 只训练 HFRE、区域-语言连接器和新增的特殊 token；
   - 目标：让 LLM 学会把一个区域 token 当作视觉实体读取。
2. **感知指令微调（Perception Instruction Tuning）**
   - 解冻更多参数；
   - 混合检测、指代理解（REC）、区域 captioning、区域推理、计数、OCR 等数据；
   - 同时加入通用指令数据，防止语言能力遗忘；
   - 加入拒绝样本，使目标不存在时能回答“不存在”。

### 3.2 VLX-Seek 1.5 的改动

官方博客只给出定性描述，未披露具体层数、数据配比与 backbone 型号：

- **更强的 Aux Vision Tower**：提升视觉-语言对齐与纯视觉特征质量，改善视觉相似实例的区分。
- **更强的 VLM backbone**：具体基座未披露。
- **更多 Linear Attention 层**：降低推理与显存开销。
- **更快的 OPN**：缩短候选生成时间；具体加速比未披露。
- **hard-negative 拒识训练 + 显式 `None`**：减少不存在目标的幻觉。
- **数据扩展**：加入无人机、监控、机器人视角等具身场景，覆盖小目标、密集布局、非常规视角、长尾类别。

> 官方未披露：OPN 结构、HFRE 的具体层数与通道、SimpleFP 的融合方式细节、训练数据规模与配比、VLM backbone 型号、全部超参数。本笔记不补写这些数字。

## 5. 局限

1. **不是论文，缺少可核验的技术细节**：没有 arXiv、没有正式论文，OPN 结构、HFRE 细节、数据配比、backbone 型号、训练超参均未完整披露。
2. **OPN 未开源**：官方仓库用 WeDetect-Base-Uni 替代内部 OPN，因此复现的不是官方博客的完整系统。
3. **模型权重覆盖不全**：官方计划 0.6B/3B/10B，当前只开源 **10B** 推理代码与权重；3B 只报告结果，0.6B 尚未发布。
4. **结果表是图片**：官方 Table 1–6 以图片形式给出，正文没有逐项数值；本笔记的数字来自图片核对，但仍建议以官方原表为准。
5. **指标口径容易误读**：Table 1 是 F1@IoU，不是 COCO AP；Table 4 RefDrone 同时有 instance/image 级 F1/Acc，不能混用。
6. **依赖候选质量**：区域检索的上限由 OPN/替代检测器的召回决定；候选漏掉目标时，LLM 无法补救。
7. **具身场景数据未公开**：1.5 声称加入无人机、监控、机器人视角数据，但未发布数据或配比，领域泛化难以独立验证。

## 本文涉及到的模型具体结构

| 模块 | 结构 | 说明 |
|---|---|---|
| 候选生成 | OPN（内部实现未开源） | 类无关前景候选；仓库以 WeDetect-Base-Uni 替代，也可传任意 `bbox-list` |
| 区域编码 | HFRE | 语义通路 + 高分辨率细节通路，输出区域级特征 |
| 多尺度增强 | SimpleFP | 基于 ViTDet SimpleFPN，为 ViT 特征补多尺度 |
| 区域-语言连接 | region-language connector | 将区域特征投影到 LLM embedding 空间 |
| 区域表示 | `<obj*>` / `<region*>` token | 每个候选对应一个可寻址 token |
| 语言模型 | 未披露具体 VLM backbone（1.5 称更强） | 全局图像 token + 文本 token + 区域 token 联合推理 |
| 模型家族 | 0.6B / 3B / 10B | 0.6B 规划；3B 报告结果；10B 开源权重 |
| 推理加速 | 更多 Linear Attention 层、更快 OPN | 1.5 改动，具体层数/加速比未披露 |

**推理流程**:
1. 输入图像与文本查询；
2. OPN/替代检测器生成候选框；
3. HFRE + SimpleFP 提取每个候选的区域特征；
4. 投影为区域 token，与图像 token、文本 token 拼接；
5. LLM 输出匹配的区域 ID（如 `<obj3>`）及自然语言答案；
6. 目标不存在时输出 `None`。

## 实验的全部流程

### 数据与训练阶段
1. 官方未披露 1.5 的预训练数据规模、配比与 backbone；仅说明加入无人机、监控、机器人视角等具身场景数据。
2. Stage 1 区域-语言对齐：冻结 VLM 主干，训练 HFRE、区域-语言连接器与新增特殊 token。
3. Stage 2 感知指令微调：混合检测、REC、区域 caption、区域推理、计数、OCR 与通用指令数据；加入拒绝样本。
4. 1.5 增加 hard-negative rejection 训练与显式 `None` 输出格式；具体损失函数与超参未披露。

### 推理阶段
5. 候选生成：内部 OPN（未开源）或 WeDetect-Base-Uni（仓库默认替代），也可用 `--bbox-list` 传入任意检测器。
6. 将候选框送入 HFRE + SimpleFP，得到区域特征并投影为 `<obj*>` token。
7. 拼接图像 token、查询文本、区域 token，送入 LLM。
8. LLM 输出区域引用；根据 token 与候选框映射还原框；不存在目标输出 `None`。
9. 边缘部署可使用 Linear Attention 加速内核；缺失时回退到 PyTorch 实现。

### 评测阶段
10. 通用检测：COCO、LVIS、ODinW13，Table 1 使用 F1@IoU（0.5/0.95/mean）。
11. REC：HumanRef、RefCOCOg、RefCOCO/+/g 平均（Table 2/3）。
12. 计数：PixMoCount（Table 3）。
13. 无人机：VisDrone、RefDrone（Table 4，instance/image 两级）。
14. 具身空间推理：RefSpatialBench、EmbSpatialBench（Table 5）。
15. 物体幻觉：HumanRef、VisDrone、RefDrone 的 FP/GT（Table 6，越低越好）。
16. 对比对象：Qwen3-VL、Gemini-3 Pro、Rex-Omni、LocateAnything、VLX-Seek 1.0 等。

## 个人评价

**核心价值**: VLX-Seek 把“坐标生成”换成“区域选择”，这是一条很适合端侧和具身场景的路线：LLM 不必学习精确几何回归，只需在候选集合上做语言条件检索；输出 token 更短，延迟更低，也更容易显式拒绝不存在的目标。对遥感/无人机场景，Table 4 的 RefDrone 提升（F1 inst 54.0→73.2）说明“候选 + 区域引用”对密集小目标尤其有效。

**可借鉴点**:
- **候选质量决定上限**：VLX-Seek 的收益来自 OPN/WeDetect-Uni 的候选召回；在遥感中应先保证小目标候选不漏，再谈 LLM 选择。
- **区域 token 是接口设计**：把框编码为可寻址实体，让 LLM 用“引用”代替“生成坐标”，可迁移到遥感指代、计数、变化检测中的区域问答。
- **显式拒绝**：FP/GT 指标与 hard-negative 训练对无人机/监控很重要，可避免“每个查询都框一个东西”。
- **端侧优化**：Linear Attention、候选缓存、短输出 token 都是实际部署考虑，而不是单纯刷榜。
- **但要注意证据强度**：这不是论文，缺少消融与训练细节；Table 1 用 F1@IoU 而非 AP，不能直接与 COCO 检测器比较。引用时应标注“官方项目自报”。

**实验设计亮点**:
- 评测覆盖通用检测、REC、计数、无人机、具身空间推理、幻觉六个维度，且专门报告 FP/GT，直面“拒绝”能力。
- 同时报告 3B 与 10B，暴露“规模不总是更好”（COCO、ODinW13、RefDrone 幻觉）。
- 无人机场景单独成表，RefDrone 的 instance/image 两级指标比单一 mAP 更能反映密集小目标定位质量。
- 官方公开六张结果表原图，至少可核对数字，不像纯营销页面只给结论。

## 疑问解答 (Q&A)

### Q1: VLX-Seek 是论文吗？为什么没有 arXiv？

**答**：不是论文。官方仓库的引用格式是 `@misc{omailab2026vlxseek, ...}`，官方 1.5 博客没有 arXiv 编号、没有 BibTeX、没有正式技术报告。它属于“开源模型 + 官方技术博客”。因此本笔记不能按论文的“原文公式/实验设置”标准要求它；所有未披露项都已标注。

### Q2: 为什么用区域 token 代替坐标？只是输出更短吗？

**答**：不只是短。坐标是长数字序列，容易出现格式、顺序、归一化错误；多目标时还要串行生成。区域 token 把定位变成“从候选集合中选 ID”，LLM 只需输出少量 token，且候选框由外部检测器保证几何精度。这样既降低解码延迟，也避免 LLM 直接回归坐标的精度缺陷。

### Q3: OPN 是什么？为什么仓库里变成了 WeDetect？

**答**：OPN（Omni Proposal Network）是官方博客中的类无关候选生成器，负责召回前景区域。官方 README 明确说明，受公司政策限制，**内部训练的 OPN 未开源**；仓库集成开源的 **WeDetect-Base-Uni** 作为替代，也允许用户通过 `--bbox-list` 传入任意检测器的候选框。因此复现的候选质量取决于替代检测器，不等同于官方完整系统。

### Q4: 0.6B、3B、10B 都开源了吗？

**答**：没有。官方计划 0.6B/3B/10B 三档；当前开源的是 **10B** 的推理代码与权重，3B 只在官方博客报告结果，0.6B 仍是规划。引用 3B 数字时要注意它是官方自报、权重未发布。

### Q5: Table 1 的 59.1 是 COCO mAP 吗？

**答**：不是。Table 1 的 COCO/LVIS 列是 **F1@IoU**（0.5、0.95、mean），ODinW13 才是 mAP。微信公众号文章里“COCO 45.3 mAP”与 Table 1 的 59.1 不是同一指标，不能直接比较；本笔记只采用官方表的值，并标注口径。

### Q6: 物体幻觉 FP/GT 怎么定义？1.5 真的更好吗？

**答**：官方定义是 FP / Number of GT Objects：对“请求但图中不存在”的目标产生的假阳性数，除以 GT 目标数，越低越好。Table 6 显示 1.5-3B 从 15.1/10.5/30.3 降到 14.1/8.7/18.0（HumanRef/VisDrone/RefDrone），提升明显；但 1.5-10B 在 RefDrone 上为 19.6，反而高于 3B 的 18.0，说明规模不必然降低所有场景的幻觉。

### Q7: 训练分几阶段？1.5 改了什么？

**答**：1.0 是两阶段：区域-语言对齐（冻结 VLM 主干，训练 HFRE、连接器、特殊 token）→ 感知指令微调（检测、REC、caption、计数、OCR 等混训，加拒绝样本）。1.5 在此之上增加：更强 Aux Vision Tower、更强 VLM backbone、更多 Linear Attention、更快 OPN、hard-negative 拒识、显式 `None` 格式、无人机/监控/机器人视角数据。具体数据配比、backbone 型号、损失函数未披露。

### Q8: 没有 OPN 还能用吗？如何接入自己的检测器？

**答**：可以。仓库默认在未传 `--bbox-list` 时加载 WeDetect-Base-Uni 生成候选；也可以把任意检测器的框转成像素坐标 `[x1,y1,x2,y2]`，通过 `--bbox-list` 传入。对遥感场景，可以换成领域检测器（如小目标检测器）来保证候选召回，再用 VLX-Seek 做区域选择与拒绝。
