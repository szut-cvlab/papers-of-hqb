## 摘要

**问题**: SAM 1/2 的 **Promptable Visual Segmentation（PVS）** 用点、框、掩码一次分割**一个**对象；它们没有解决“找出并分割某个概念在图像/视频中出现的**所有**实例”这一更一般的任务。例如，给一句“cats”，要找出视频里所有猫并保持身份。

**方案**: 提出 **SAM 3**，统一支持图像/视频的 **Promptable Concept Segmentation（PCS）**：
- 概念提示（concept prompts）可以是短名词短语（如“yellow school bus”）、图像示例（正/负框），或两者组合；
- 返回所有匹配实例的分割掩码与唯一身份 ID；
- 同时保留并改进 SAM 2 的 PVS 能力。

**关键创新/贡献**：
- **创新点1（PCS 任务与 SA-Co 基准）**: 形式化 PCS；构建 SA-Co 基准，含 **270K** 唯一概念，比现有基准多 **50×** 以上；训练数据覆盖 **4M** 唯一概念。
- **创新点2（detector + tracker 解耦）**: 图像级 DETR 式检测器负责“识别+定位”，SAM 2 式 tracker 负责视频传播与身份；二者共享 Perception Encoder（PE）骨干，避免检测（身份无关）与跟踪（身份分离）的任务冲突。
- **创新点3（Presence Head）**: 用全局 presence token 单独预测“概念是否存在”，把识别与定位解耦；每个 proposal 只判断“在概念存在的前提下是否匹配”，最终分数为二者乘积。
- **创新点4（人 + AI 数据引擎）**: 媒体策展、标签策展、标签验证三方面创新；用 Llama 3.2 微调的 AI verifier 做 mask/exhaustivity 验证，吞吐约翻倍。

**验证**:
- 零样本 LVIS mask **AP 48.5**（前最佳 38.5）；SA-Co Gold **cgF 54.1**，是 OWLv2* 24.6 的 **2 倍以上**，达到人类 72.8 的 **74%**（Table 1）。
- 零样本 COCO box **AP 56.4**、COCO-O **55.7**；SA-Co Gold box **55.7**（Table 1）。
- 视频 PCS：SA-V **cgF 30.3 / pHOTA 58.0**，YT-Temporal-1B **50.8 / 69.9**，SmartGlasses **36.4 / 63.6**（Table 5）。
- PVS：MOSEv2 **60.3**（比 SAM 2.1 高 12.4），DAVIS17 **92.2**，SA-V test **84.4**（Table 6）。
- 计数：CountBench **MAE 0.12 / Acc 93.8**，PixMo-Count **0.21 / 86.2**（Table 4）。

## 1. 引言

**背景 & 动机**:
- “在视觉场景中找到并分割任何东西”是多模态 AI 的基础能力，支撑机器人、内容创作、AR、数据标注与科学发现。
- SAM 系列提出可提示分割，但 SAM 1/2 的 PVS 是“一个提示 → 一个对象”；现实问题常是“找出某概念的所有实例”，如视频里所有“cats”。
- 现有开放词汇检测/分割（OWLv2、Grounding DINO、APE、DINO-X）多为图像级、单帧、或缺少视频身份保持；通用 MLLM 可输出框/掩码，但缺少统一、可交互的概念分割接口。

**本文思路**:
- 把任务扩展为 PCS：输入图像/短视频（≤30 秒）、短名词短语、图像示例；输出所有匹配实例的掩码 + 唯一 ID。
- 模型由 **detector + tracker** 组成，共享 PE 骨干：detector 做图像级概念检测，tracker 继承 SAM 2 做视频传播；检测器身份无关，tracker 负责身份分离，避免任务冲突。
- 数据是瓶颈：构建人 + AI 在环的数据引擎，自动标注 4M 唯一概念；构建 SA-Co 基准与 CGF 指标。

**贡献**:
1. 提出 PCS 任务与 SA-Co 基准。
2. 解耦识别、定位、跟踪的架构；presence head 提升开放词汇识别。
3. 高质量、高效率的数据引擎，人 + AI 互补。
4. 在图像/视频 PCS 上达到 SOTA（相对 prior 系统约 2×），同时提升 PVS；开源模型、代码、基准。

## 2. Promptable Concept Segmentation（PCS）

**任务定义**:
给定图像或短视频（≤30 秒），检测、分割并跟踪由以下提示指定的视觉概念的**所有**实例：
- 短名词短语（NP，名词 + 可选修饰语）；
- 图像示例（正/负 bounding box）；
- 两者组合。

**提示属性**:
- 名词短语提示对图像/视频的所有帧是**全局**的；
- 图像示例可给在**单帧**上，作为正/负框，迭代**精化**目标掩码；
- 所有提示必须在类别定义上一致；例如不能用“鱼尾”去精化“鱼”，应更新文本提示。
- 示例特别适合：模型漏检某些实例、概念罕见、需要排除误检。

**开放性带来的歧义**:
- 词义多义（“mouse” 鼠标 vs 动物）；
- 主观描述（“cozy”“large”）；
- 模糊/依赖语境、甚至不可 ground 的短语（“brand identity”）；
- 边界歧义（“mirror” 是否含框）、遮挡/模糊。
- 处理：三位专家标注测试集、允许多种合理解释的评测协议、数据管线/指南减少歧义、模型中的 ambiguity module。

## 3. 模型

SAM 3 是 SAM 2 的泛化：同时支持 PCS 与 PVS；输入概念提示或视觉提示（点、框、掩码），输出对象/掩码/掩码序列。

### 3.1 Detector 架构

- **双编码器-解码器 Transformer**：DETR 式检测器 + SAM 2 式 tracker。
- **骨干**：对齐的 **Perception Encoder（PE）**，图像与文本共享；图像示例由 exemplar encoder 编码。
- **Prompt tokens**：图像示例 token + 文本 token。
- **Fusion encoder**：接收图像编码器的无条件 embedding，通过 cross-attention 条件于 prompt tokens；6 层 Transformer block。
- **DETR decoder**：学习 object queries 对融合后的图像 embedding 做 cross-attention；每层预测：
  - 每个 query 的 binary classification logit（是否对应 prompt）；
  - 相对上一层的 box delta（Deformable DETR 式）。
- 使用 box-region-positional bias（Plain-DETR）聚焦注意力，但保持 **vanilla attention**；训练用 DAC-DETR 双监督 + Align loss；mask head 改编自 MaskFormer；另有 semantic segmentation head 逐像素预测是否属于 prompt。

### 3.2 Presence Token

**动机**:
- 让每个 proposal query 同时做“识别（what）”和“定位（where）”很难：识别需要全图上下文，定位需要局部细节，二者冲突。

**方法**:
- 引入一个学习的全局 **presence token**，只负责预测“目标概念（NP）是否出现在图像/帧中”：

$$
p(\text{NP is present in input}).
$$

- 每个 proposal query $q_i$ 只解决定位问题：

$$
p(q_i\text{ is a match}\mid \text{NP is present in input}).
$$

- 最终每个 proposal 的分数为自身分数与 presence 分数的乘积：

$$
s_i = s_i^{\text{loc}} \cdot s^{\text{presence}}.
$$

**效果**:
- 消融：加 presence head，cgF **50.7→52.2**，image-level MCC **0.77→0.82**，pmF1 65.4→63.4（Table 8a）。
- 识别与定位解耦，尤其利于带 hard negative 的训练。

### 3.3 图像示例与交互

- 每个图像示例 = 一个 bounding box + 一个二值标签（正/负）。
- Exemplar encoder 分别编码：
  - 位置 embedding；
  - 标签 embedding；
  - ROI-pooled 视觉特征；
  - 拼接后经小 Transformer。
- 得到的 prompt 与文本 prompt 拼接为 prompt tokens。
- 图像示例可单独使用，也可补充文本；例如给一个“狗”的正框，模型检测图中**所有**狗，而不是只分割这一只（区别于 PVS）。
- 可根据当前检测错误迭代添加正/负示例，精化输出。

### 3.4 Tracker 与视频架构

给定视频与提示 $P$，detector 每帧检测新对象，tracker 传播上一帧的 masklet：

$$
\hat{\mathcal{M}}_t=\mathrm{propagate}(\mathcal{M}_{t-1}),
$$

$$
\mathcal{O}_t=\mathrm{detect}(I_t,P),
$$

$$
\mathcal{M}_t=\mathrm{match\_and\_update}(\hat{\mathcal{M}}_t,\mathcal{O}_t).
$$

- **Masklet 初始化**：第一帧每个检测对象初始化一个 masklet。
- **传播**：后续帧用 SAM 2 式单帧传播，基于上一帧 masklet 预测新位置；PE 骨干在 detector 训练后冻结，tracker 按 SAM 2 训练（prompt encoder、mask decoder、memory encoder、memory bank）。
- **Memory**：只保留对象高置信存在的帧；mask decoder 是 encoder hidden states 与 output tokens 的双向 Transformer；每帧预测 3 个掩码及置信度，选最高。
- **匹配/更新**：tracked masks 与当前帧检测用简单 IoU matching；未匹配的新检测 spawn 新 masklet。
- **时序消歧**：
  1. **masklet detection score**：统计时间窗口内 masklet 与检测匹配的帧数；低于阈值则抑制。
  2. **re-prompt**：周期性用高置信检测掩码替换 tracker 自身预测，避免遮挡/干扰物导致的漂移。
- **实例精化**：得到初始 masks/masklets 后，可用正/负 click 精化单个 mask，再传播到整个视频。

### 3.5 训练阶段

四阶段：
1. **PE 预训练**：5.4B 图文对，对比学习，视觉/文本编码器对齐。
2. **Detector 预训练**：大规模图像分割/检测数据。
3. **Detector 微调**：高质量 SA-Co 数据 + hard negatives。
4. **Tracker 训练**：冻结 PE，按 SAM 2 训练视频跟踪组件。

模型约 **850M** 参数：视觉编码器 ~450M、文本编码器 ~300M、detector/tracker ~100M。

## 4. 数据引擎

目标：构建大规模、多样概念、细粒度掩码的训练数据；用模型失败案例驱动标注。

**四个组件**:
1. **Media mining**：用 curated ontology 从大规模图像/视频池中挖掘媒体；覆盖 12 个媒体域（web、艺术、食物、驾驶、热成像等）。
2. **NP proposal**：AI 模型（captioner/parser、Llama-based pipeline）提出名词短语；后期加入 adversarial hard negatives。
3. **Mask proposal**：用当前 SAM 3 / SAM 2 + open-vocabulary detector 生成候选掩码。
4. **Verification**：
   - **Mask Verification（MV）**：接受/拒绝掩码质量与相关性；
   - **Exhaustivity Verification（EV）**：检查是否覆盖该 NP 的所有实例；
   - 未通过 EV 的送人工修正（加/删/编辑掩码，或用 group mask 处理难分小目标）；
   - 不可 ground/歧义短语可拒绝。

**四阶段**:
- **Phase 1（Human Verification）**：随机采样图像 + 简单 captioner/parser 的 NP；初始 mask proposal = SAM 2 + off-the-shelf OV detector；人工验证；收集 **4.3M** image-NP 作为初始 HQ 数据；训练 SAM 3 作为下一阶段 mask proposal。
- **Phase 2（Human + AI Verification）**：用 Phase 1 的 MV/EV 人工标签微调 **Llama 3.2**，得到 AI verifier；自动验证，人工聚焦困难样本；SAM 3 重训 6 次；新增 **122M** image-NP；NP proposal 升级为 Llama pipeline，加入 hard negative。
- **Phase 3（Scaling & Domain Expansion）**：扩到 15 个数据集；MV AI verifier 零样本可用，EV 需少量域内人工监督；从 alt-text 与 **22.4M 节点 ontology**（Wikidata，17 顶级类/72 子类）挖掘长尾概念；SAM 3 重训 7 次、AI verifier 3 次；新增 **19.5M** image-NP。
- **Phase 4（Video Annotation）**：用成熟图像 SAM 3 收集视频特定质量标注；场景/运动过滤、内容平衡、排序、定向搜索；采样帧走图像标注流程；生成 masklet，去重/去 trivial；人工聚焦拥挤目标与跟踪失败；得到视频训练集。

**效果**: AI verifier 使数据引擎吞吐约翻倍；Phase 2/3 逐步把人工从“标注”转向“修正最难错误”。

## 5. SA-Co 数据集与基准

### 5.1 训练数据

三类图像数据：
1. **HQ**：数据引擎 Phase 1-4 的人工高质量数据；4M 唯一 NP，最大高质量开放词汇分割数据集。
2. **SYN**：成熟数据引擎（Phase 3）自动标注、无人工参与。
3. **EXT**：15 个外部实例分割数据集，用 ontology pipeline 加 hard negatives。

视频数据：**TrainVid**，含视频与唯一 NP，平均约 6 fps；平均帧数等细节见附录。

### 5.2 SA-Co Benchmark

- **270K** 唯一短语，图像+视频，>50× 现有基准概念数。
- 4 个 split：
  - **Gold**：7 个域，每个 image-NP 由 3 位标注者标注，用于测人类性能；
  - **Silver**：10 个域，每个 image-NP 仅 1 个人工标注；
  - **Bronze**：9 个已有数据集，有掩码或由 SAM 2 以框为提示生成；
  - **Bio**：生物/细粒度域。
- **SA-Co/VID**：3 个域，每个 video-NP 1 位标注者。

### 5.3 指标

只评估置信度 **>0.5** 的预测，模拟下游使用并强调校准。

- **pmF1（positive micro F1）**：在至少有一个 GT 掩码的正 media-phrase 对上衡量定位。
- **ilMCC（image-level Matthews Correlation Coefficient）**：图像级二分类“概念是否存在”，范围 [-1,1]，不看掩码质量。
- **CGF（classification-gated F1）**：

$$
\mathrm{CGF}=100\times \mathrm{pmF1}\times \mathrm{ilMCC}.
$$

- **pHOTA**：视频跟踪的关联/分割综合指标。
- **歧义处理**：Gold 每个 NP 3 个标注，oracle 评估取与任一 GT 最匹配的分数。

## 7. 相关工作

- **可提示/交互式分割**：SAM 1 引入点/框/掩码交互；SAM 2 扩展到视频 PVS；SAM 3 增加文本/图像示例概念提示，分割所有实例。
- **图像开放词汇检测/分割**：OWLv2、Grounding DINO、APE、DINO-X 等用 CLIP 式视觉-语言编码器做开放类别；SAM 3 用 DETR 检测器 + presence head + 大规模数据，并扩展到视频。
- **视觉 grounding**：GLIP、Grounding DINO 把检测当 phrase grounding；GLEE 支持文本/指代/视觉提示但不支持 exemplar 交互；SAM 3 统一 PCS/PVS 并支持交互精化。
- **多目标跟踪/分割**：tracking-by-detection（SORT、ByteTrack、OC-SORT）、端到端（TrackFormer、TransTrack、MOTR）；SAM 3 用 detector + SAM 2 tracker 解耦，避免检测/跟踪任务冲突。
- **MLLM 工具**：LISA、GLaMM、Gemini 2.5、Molmo 可输出框/掩码/点；SAM 3 可作为 MLLM 的视觉工具（Agent）。

## 8. 结论

**总结**:
- 提出 PCS 任务与 SA-Co 基准，把可提示分割从“单实例”扩展到“概念的所有实例”。
- 架构解耦识别、定位、跟踪：detector + tracker 共享 PE；presence head 解耦识别/定位。
- 人 + AI 数据引擎产出 4M 概念、高质量掩码；AI verifier 吞吐翻倍。
- 在图像/视频 PCS 上约 2× 于 prior 系统，同时提升 PVS；开源模型、代码、基准。

**局限**（Appendix）:
- 对细粒度域外概念（飞机型号、医学术语、热成像）零样本泛化弱；需少量微调或域特定合成数据。
- 只支持简单名词短语，不支持多属性/长指代表达；需接 MLLM 处理复杂查询。
- 视频推理成本随对象数线性增长；实时 30 FPS 需多 GPU（2 H200 约 10 对象、4 H200 约 28、8 H200 约 64）。
- 多目标跟踪缺少共享对象级上下文，拥挤场景消歧有限。
- 概念级与实例级交互需硬“模式切换”，尚不能无缝混合。

## 个人评价

**核心价值**: SAM 3 把“分割一切”从**几何提示**推进到**概念提示**：不是“点一下分一个”，而是“说一个概念，分所有实例并跟踪”。它的关键不是更大的模型，而是三点工程/研究判断：
1. **识别与定位解耦**（presence head）——让 proposal 不必同时学“有没有”和“在哪”；
2. **检测与跟踪解耦**——detector 身份无关，tracker 负责身份，避免任务冲突；
3. **数据引擎**——人 + AI verifier 把 4M 概念的数据成本压到可承受范围。
这三点的组合，使 PCS 从“不可做”变成“可评测、可开源、可落地”。

**可借鉴点**:
- 对遥感/无人机：PCS 的“概念 → 所有实例 + 身份”非常适合**地物要素提取**（所有“建筑物”、所有“小船”、所有“受损屋顶”），视频版本可用于无人机跟踪。
- **presence head** 可迁移到任何“开放词汇检测 + 拒识”场景：先判断概念是否存在，再定位，能显著降低 hard negative 误检。
- **detector-tracker 解耦**：遥感视频/多时相跟踪中，检测器不必学身份，跟踪器单独学关联，工程上更易维护。
- **数据引擎**：AI verifier 做 mask/exhaustivity 质检，人只修最难样本；对遥感标注（地物掩码、变化区域）很有参考价值。
- **CGF 指标**：把定位（pmF1）与图像级识别（ilMCC）相乘，避免“框得准但根本不该检”或“识别对但掩码差”被平均分掩盖；遥感开放词汇评估可借鉴。
- **注意成本**：视频推理随对象数线性增长，实时需多 GPU；边缘部署需蒸馏/量化。

**实验设计亮点**:
- 同时评图像 PCS、视频 PCS、PVS、few-shot、计数、Agent，覆盖“概念理解 + 定位 + 跟踪 + 推理”全链路。
- 新基准 SA-Co 含 270K 概念、Gold 三人标注，且报告人类上限（72.8），让 54.1 的绝对水平可解释。
- 消融把 presence、hard negatives、HQ/SYN/EXT、AI verifier 分开，证据链完整。
- 与 OWLv2、Grounding DINO、LLMDet、DINO-X、APE、T-Rex2、GLEE 等多类基线对比，定位清晰。
- 诚实报告 RF100VL 零样本略低于 gDino、YTVIS 低于 GLEE、视频实时需多 GPU 等短板。

## 疑问解答 (Q&A)

### Q1: PCS 与 PVS 的区别是什么？

**答**：PVS（SAM 1/2）是“一个几何提示 → 一个对象”，点是哪个就分哪个；PCS（SAM 3）是“一个概念提示 → 所有匹配实例”，文本“cat”会返回图中所有猫，视频中还保持每个实例的身份。PCS 还支持正/负图像示例做概念级检索与精化，而 PVS 的示例只影响单个实例。

### Q2: Presence head 为什么能提升识别？它的分数怎么用？

**答**：让每个 proposal 同时学“是什么”和“在哪”会冲突：识别需要全局上下文，定位需要局部细节。Presence token 只预测“这个概念在图中是否存在”，proposal 只预测“在存在的前提下是否匹配”。最终分数是局部匹配分 × presence 分。这样 hard negative（不存在的概念）会被 presence 门控压掉，消融中 ilMCC 从 0.77 提到 0.82。

### Q3: 为什么 detector 和 tracker 要解耦？

**答**：检测器需要**身份无关**——同一概念的所有实例都该检出；tracker 需要**身份分离**——把不同帧的同一实例关联起来。若用一个端到端模型同时做，两者目标冲突。SAM 3 让 detector 做图像级检测，tracker 继承 SAM 2 做传播，共享 PE 骨干但分开训练，避免任务干扰。

### Q4: 数据引擎中 AI verifier 具体做什么？为什么能翻倍吞吐？

**答**：AI verifier 用 Llama 3.2 在 Phase 1 的人工 MV/EV 标签上微调，输入 image-phrase-mask 三元组，输出 mask 质量/穷尽性的多选评级。它自动完成大部分“接受/拒绝/是否漏实例”的判断，人只修正最难错误。这样人工从“逐条标注”转为“处理失败案例”，吞吐约翻倍。

### Q5: CGF 指标怎么算？为什么不直接用 AP？

**答**：CGF = 100 × pmF1 × ilMCC。pmF1 衡量正样本上的定位/掩码质量，ilMCC 衡量图像级“概念是否存在”的分类质量。AP 不关心校准，且可能让“框得准但误检很多”或“识别对但掩码差”被平均掉；CGF 把两者相乘，更贴近下游“先判断有没有、再分割”的使用方式。论文只评估 confidence>0.5 的预测，进一步强调校准。

### Q6: SAM 3 与 SAM 2 在 PVS 上是什么关系？

**答**：SAM 3 保留并改进 PVS：MOSEv2 60.3 vs SAM 2.1 47.9（+12.4），DAVIS17 92.2，SA-V test 84.4。交互式图像分割 1-click 66.1 略低于 SAM 2.1 的 66.4，但 3/5 clicks 更高（81.3/85.1 vs 80.3/84.3）；FPS 43.5 低于 SAM 2.1 的 93.0，因为模型更重。

### Q7: 论文里 LVIS mask AP 到底是 48.5 还是 48.8？

**答**：Table 1 写 **48.5**，引言写 **48.8**（“48.8 vs 38.5”）。这是原文内部口径不一致；本笔记以 Table 1 的 48.5 为准，并在正文标注差异。引用时建议写“约 48.5–48.8”。

### Q8: SAM 3 的主要局限是什么？

**答**：
1. 对细粒度域外概念（飞机型号、医学术语、热成像）零样本弱，需微调或域特定合成数据；
2. 只支持简单名词短语，复杂指代/多属性需接 MLLM；
3. 视频推理随对象数线性增长，实时需多 GPU；
4. 多目标跟踪缺少共享对象级上下文，拥挤场景消歧有限；
5. 概念级/实例级交互需硬模式切换，尚不 seamless。
