## 摘要

**问题**: 开放词汇目标检测（Open-Vocabulary Object Detection, OVD）需要根据文本提示检测任意类别。带深度跨模态融合层的方法精度高，但融合计算昂贵，且视觉特征会随文本查询变化，无法在不同查询间复用；例如 Grounding-DINO 在 LVIS 的 1203 类上按 chunk size 40 评测需要 **31 次前向**，单图延迟达数秒。

**方案**: 重新审视**无融合（non-fusion）的双塔架构**，把检测识别视为**检索**：图像区域特征与文本查询在同一嵌入空间中做点积匹配。提出 **WeDetect** 模型族：
1. **WeDetect**：实时开放词汇检测底座；
2. **WeDetect-Uni**：冻结检测器、只学一个 objectness prompt 的通用候选生成器，支持新任务 **object retrieval**（从历史数据中检索包含指定物体的图像）；
3. **WeDetect-Ref**：把大视觉语言模型（LVLM）当分类器，对候选框做并行二分类，完成指代理解（Referring Expression Comprehension, REC），不做逐 token 坐标生成。

**关键创新/贡献**：
- **创新点1（检索式检测）**: 去掉跨模态融合，保留 CLIP 式双塔，通过精心整理的数据与充分训练，让非融合检测器超过融合模型，同时保持实时推理。
- **创新点2（数据引擎）**: 用 objectness 检测器 + SAM mask + 微调的 Qwen2.5-VL 7B 自动生成“粗类→细类→实例描述”的多粒度层级标签，构建 15M 图像、330M 框的自标注数据集。
- **创新点3（通用候选生成 + 物体检索）**: 冻结检测器，仅训练一个 objectness prompt；候选框的 box embedding 仍具类别判别性，可缓存用于快速物体检索。
- **创新点4（LMM 分类式 REC）**: 用 Qwen3-VL 对候选框并行二分类，单次前向输出所有候选分数，避免 next-token 串行解码，REC 相对 Qwen3-VL 4B 提速 **13 倍**。

**验证**:
- LVIS minival：Tiny **37.4 AP @ 62.5 FPS**（33M 参数），Base **47.3 AP**，Large **55.0 AP**；LVIS val 上 Large **49.4 AP**，超 T-Rex2 **3.6 AP**（Table 1）。
- Object retrieval：WeDetect-Large-Uni **F1 83.6**，OpenAI CLIP **46.4**（+37.2）（Table 4）。
- REC：WeDetect-Ref 4B 在 RefCOCO/+/g 平均 **93.2**，超 Qwen3-VL 4B **6.6** 分，**快 13 倍**（Table 2）。
- LMM 检测：WeDetect-Ref 4B COCO **50.0 AP**，是首个突破 50 AP 的 LMM（Table 5）。
- 15 个 benchmark 上报告 SOTA 或强竞争力结果。

## 1. 引言

**背景 & 动机**:
- 图像识别已从闭集分类走向开放词汇检索；开放词汇检测进一步要求根据文本提示定位任意类别。
- 主流 OVD 方法（GLIP、Grounding-DINO、LLMDet）通过深度跨模态融合提升对齐，但融合层计算密集，推理效率低。
- 更关键的是：**融合使视觉特征变成 query-specific**，不同文本查询无法共享同一份视觉特征。Grounding-DINO 在 LVIS 1203 类上必须分 31 次前向，延迟不可接受。
- 非融合双塔方法（CLIP 式）可以预计算图像与文本表示，只做一次点积即可响应新查询，但此前在开放词汇检测精度上不如融合模型。

**本文贡献**:
1. **WeDetect**：从预训练 CLIP 微调的双塔检测器；用 ConvNeXt 多尺度视觉塔、CSPRepBiFPAN neck、YOLO-World 对比头；分类只做图像网格特征与类名 embedding 的点积。
2. **数据引擎**：构建 15M 图像、330M 框的高质量开放词汇检测数据，带多粒度层级标签。
3. **WeDetect-Uni**：冻结检测器，只训练通用 objectness prompt；高召回候选生成，并支持以图搜物的 **object retrieval**。
4. **WeDetect-Ref**：用 LVLM 对候选框做并行二分类，完成复杂指代理解，避免坐标生成与串行解码。
5. **实验**：在 LVIS、COCO、COCO-O、ODinW、RefCOCO/+/g、HumanRef、D³ 等 15 个 benchmark 上验证，兼顾精度与速度。

## 2. 相关工作

### 2.1 开放词汇目标检测

现有工作主要沿四个方向：
1. **训练数据构建**：GLIP 统一检测与 phrase grounding，用区域-词对比预训练利用海量图文对；后续工作构造硬负样本、扩大数据与算力。
2. **训练目标**：除区域-词对比外，引入掩码语言建模、密集描述、与 LLM 联合训练等，增强语言知识。
3. **视觉-语言融合层**：GLIP、FIBER、Grounding-DINO、OV-DINO、Prompt-DINO 等用深度融合提升对齐，但融合计算昂贵且视觉特征无法跨查询共享。
4. **模型蒸馏**：ViLD、OADP、LLMDet 等从基础模型蒸馏开放词汇知识。

**本文定位**：重新审视深度融合的必要性，回到简单双塔，用检索范式统一检测、候选生成与 REC。

### 2.2 大型视觉语言模型

- LVLM（Qwen2.5-VL、Qwen3-VL、InternVL 等）具备世界知识、推理与开放词汇感知能力。
- 为增加区域感知，常见做法是把每个对象编码为特殊 token；但语言建模目标把数字拆成离散 token 并用交叉熵优化，**对精确坐标不敏感**。
- 另一类方法用额外解码器或预提取候选框让 LLM 引用，但仍采用 **next-token prediction**，对象必须串行解码，推理速度受限。
- 本文把 LLM 当**并行分类器**，对候选列表一次性打分，兼顾语言理解与速度。

## 3. WeDetect：强检测底座

### 3.1 模型架构

WeDetect 是双塔架构（Figure 1a）：
- **文本塔**：XLM-RoBERTa 初始化，编码类别名；每个类名单独编码为一个 embedding。
- **视觉塔**：YOLO 风格架构：
  - ConvNeXt 骨干，输出多尺度特征；
  - CSPRepBiFPAN neck；
  - YOLO-World 对比头；
  - 无任何跨模态融合层。
- 分类：图像网格特征与类名文本 embedding 直接做**点积**；损失函数与标签分配与 YOLO-World 相同（区域-文本对比分类损失 + 框回归损失）。
- 由于没有融合，文本 embedding 与图像特征都可预计算/缓存，新查询只增加一次点积。

### 3.2 数据集构建

**源图像采样**:
- 从 SAM-1B、LAION、CC12M、Zero、以及从授权网站自采图像中采样，共 **15M** 张，覆盖广泛概念与领域。
- 原始图文对中的 caption 用于挑选稀有名词，平衡概念分布。

**框标注流水线（数据引擎）**:
1. 用所有可用检测数据集训练一个 **objectness 检测器**，召回图中所有目标，保证标注完整性。
2. 用 **SAM** 生成每个目标的 mask；在图像上高亮物体边界，并把框坐标作为文本输入，增强标注器的局部感知。
3. 用微调后的 **Qwen2.5-VL 7B** 生成实例级层级标签，例如狗标注为 `animal, dog, a yellow dog`（粗类→细类→实例描述）。
4. 微调标注器以具备两种能力：**结构化输出**（固定模板、先粗后细）与**拒识**（错误框不生成标签，直接丢弃）。
5. 标注器训练完成后，可无人工监督地标注剩余图像。

**数据规模**:
- 自标注 15M 图像、330M 框。
- 另加入开源检测/grounding 数据：OpenImagesV6、Objects365 V2、V3Det、ImageNetBox、GoldG，约 **5M** 样本（附录数据表）。
- 总计约 **20M** 样本。

### 3.3 模型训练

**分阶段训练（staged-wise training）**:
1. **图像级对比预训练**：用 CLIP 式图像-文本对比目标在大规模图文数据上预训练，得到视觉骨干与语言编码器初始化。
2. **冻结双塔，训练 neck/head**：neck 与 head 仍随机初始化，若直接端到端会破坏预训练特征；先冻结视觉骨干与语言编码器，只训练剩余组件。
3. **全参数端到端**：所有参数联合训练，把图像级对齐迁移到区域级。

**多粒度标签采样**:
- 每个对象有多个候选标签；每次训练迭代**独立采样一个**标签。
- 这既为单个对象提供丰富监督，也为整个 batch 构造动态、多样的“训练时词表”，提供多样负样本，显著提升开放词汇性能。

## 4. WeDetect-Uni：通用候选生成器

**核心思想**: 不需要用户提供文本提示，也能提取图中所有可能的目标候选。

**方法**:
- **冻结整个 WeDetect 检测器**，只训练一个**通用 objectness prompt** 用于分类；这相当于在冻结特征上做 linear probing。
- 由于检测器被冻结，top-scoring proposals 对应的 box embedding 仍保持**类别特定性**，可用于后续分类。
- 只需一个可学习 prompt 即可获得高召回；不同于 RPN 等类无关候选网络，这里的候选 embedding 具有开放词汇判别力。

**新任务：object retrieval（物体检索）**:
- 目标：从图像数据库中检索所有包含用户指定物体类别的图像，尤其关注小物体（如烟头）。
- 与图文检索的区别：图文检索关注整图全局语义；物体检索关注**局部语义**。
- 评测方式：在检测数据集上，以类别名为查询、整个验证集为数据库、包含该类标注的图像为 ground truth；计算 precision、recall、F1。
- 使用方式：
  1. 用 WeDetect-Uni 提取每张图的 top-scoring proposals；
  2. 缓存这些框的 box embeddings，作为该图的“物体集合表示”；
  3. 新查询到来时，只需将类名编码为文本向量，与缓存的 box embeddings 做点积排序。

## 5. WeDetect-Ref：基于 LLM 的 REC 模型

### 5.1 将 REC 建模为检索

**挑战**:
- LLM 用语言建模目标训练，数字被拆成离散 token，坐标精度差；
- next-token prediction 必须串行生成多个对象的坐标，延迟极高。

**方法**:
- 先用 WeDetect-Uni 提取对象候选列表 $\{B_i\}_{i=1}^{n}$。
- 对每个候选框，从 MLLM 视觉编码器提取多尺度 RoI 特征，经**线性 object projector** 压缩为单个 token $o_i$；边界框编码为位置 embedding 加到 object token 上。
- 将全图 token $I$、用户查询 $q$、对象 token 序列 $\{o_i\}$ 拼接送入 LLM。
- 丢弃语言建模头，改用**二分类头**，只作用于 object token 的隐藏表示：

$$
\{h_i\}_{i=1}^{n} = \mathrm{LLM}(I, q, \{o_i\}_{i=1}^{n}),
$$

$$
\{s_i\}_{i=1}^{n} = \mathrm{Sigmoid}\left(\mathrm{Classifier}(\{h_i\}_{i=1}^{n})\right) \in [0,1],
$$

其中 $s_i$ 是第 $i$ 个候选属于查询目标的分数。

- 所有候选**一次前向并行打分**，不做坐标回归、不做 next-token 解码。
- 优势：避免语言模型回归框的缺陷；充分利用 LLM 的语言理解与开放词汇能力；推理时间与候选数线性相关，而**不随目标数增加而串行增长**。

### 5.2 三阶段训练

基座为 **Qwen3-VL**，新增特殊 token `<object>` 作为每个对象的占位符。

1. **Stage 1：区域投影器训练**
   - 用 RoIAlign 从最后一层及其他深层视觉特征图提取多尺度 RoI 特征；
   - 线性层把 RoI 特征压成一个 object token；框编码为位置 embedding；
   - 只训练新引入的区域投影器，数据为 **700K** 图像级/区域级 caption 数据。
2. **Stage 2：区域感知微调**
   - 继续训练 LLM 与 projector，视觉编码器仍冻结；
   - 加入约 **1.7M** 图像级/区域级指令数据（caption、grounded conversation 等），让 LLM 准确感知特定对象。
3. **Stage 3：区域分类微调**
   - 丢弃语言建模头，训练二分类头；
   - 数据模板：输入图像 + `Please detect the "CLASSNAME" in the image.`，输出与候选数相同的 `<object>` token；
   - 使用 **sigmoid focal loss**，以 IoU 为软标签；与任意 GT 框 IoU > 0.5 的候选为正样本；
   - 只训练 LLM 与 projector。

**负样本构造**:
- 对每个检测数据集图像，选 **3 个负类名**作为负查询；
- 负类名按 WeDetect 在负类上的 top-3 置信度选取，构成硬负样本；
- 训练与评测候选均为 WeDetect-Base-Uni 的 top-100 框；
- 若某个 GT 框与所有候选都无重叠，则直接加入候选集，保证每个 GT 至少有一个正匹配。

- 打乱 proposal 顺序性能几乎不变，说明模型对候选顺序鲁棒，因果掩码没有导致位置偏置。

## 7. 结论

**总结**: 提出检索式开放词汇检测模型族：
1. **WeDetect**：无融合双塔实时检测底座；
2. **WeDetect-Uni**：冻结检测器 + 单 objectness prompt 的通用候选生成器，支持物体检索；
3. **WeDetect-Ref**：用 LVLM 并行分类候选框的 REC 模型，取消坐标生成与 next-token 解码。

在 15 个 benchmark 上取得 SOTA 或强竞争力结果，同时保持高推理速度。作者希望检索范式被社区广泛采用。

## 本文涉及到的模型具体结构

| 模块 | 结构 | 输出/说明 |
|---|---|---|
| WeDetect 文本塔 | XLM-RoBERTa | 每个类名单独编码为一个 embedding |
| WeDetect 视觉塔 | ConvNeXt（T/B/L）+ CSPRepBiFPAN neck + YOLO-World 对比头 | 多尺度特征，无跨模态融合 |
| 分类 | 网格特征 · 类名 embedding | 点积，无融合层 |
| 检测头 | anchor-free 点回归 + TAL 标签分配 + DFL + CIoU | 与 YOLO-World 一致 |
| WeDetect-Uni | 冻结 WeDetect + 一个可学习 objectness prompt | 通用候选 + 可缓存的 box embeddings |
| WeDetect-Ref | Qwen3-VL 2B/4B + RoIAlign + 线性 object projector + 二分类头 | 每个候选一个 object token，一次前向并行打分 |

**模型规格**（Table 1）：

| 模型 | 骨干 | 分辨率 | 参数 | FPS | LVIS minival AP | LVIS AP |
|---|---|---|---:|---:|---:|---:|
| Tiny | ConvNeXt-T | 640×640 | 33M | 62.5 | 37.4 | 31.4 |
| Base | ConvNeXt-B | 640×640 | 176M | 35.1 | 47.3 | 41.4 |
| Large | ConvNeXt-L | 1280×1280 | 490M | 6.0 | 55.0 | 49.4 |

**WeDetect-Ref**:
- 基座 Qwen3-VL 2B/4B；
- 每个候选框：多尺度 RoI 特征 → 线性 projector → 1 个 object token；
- bbox 位置 embedding 加到 object token；
- LLM 输出 object token 隐状态 → 二分类头 → sigmoid 分数；
- 训练/评测候选：WeDetect-Base-Uni top-100。

## 实验的全部流程

### 数据准备阶段
1. 采样源图像：SAM-1B、LAION、CC12M、Zero、授权网站自采，共 15M。
2. 用多检测数据集训练 objectness 检测器，召回所有目标框。
3. 用 SAM 生成 mask，在图像上高亮物体边界，并输入框坐标。
4. 微调 Qwen2.5-VL 7B，输出“粗类→细类→实例描述”的层级标签；错误框由拒识能力丢弃。
5. 合并开源数据 OpenImagesV6、Objects365 V2、V3Det、ImageNetBox、GoldG，共约 5M；总训练样本约 20M。

### WeDetect 训练阶段
6. 用 CLIP 式图像-文本对比目标预训练视觉骨干与语言编码器。
7. 冻结视觉骨干与语言编码器，训练随机初始化的 neck/head，20 epoch，lr $5\times10^{-4}$。
8. 全参数端到端训练 30 epoch，lr $1\times10^{-5}$，总 batch 320。
9. 每轮对每个对象从多粒度标签中随机采样一个标签，构造动态词表与负样本。
10. 检测损失：区域-文本对比分类 + CIoU 框回归 + DFL，TAL 标签分配。

### WeDetect-Uni 阶段
11. 冻结整个 WeDetect 检测器。
12. 只训练一个可学习 objectness prompt，做类无关候选分类。
13. 推理时取 top-300 候选及对应 box embeddings，缓存；新查询只需文本 embedding 与缓存做点积。

### WeDetect-Ref 训练与推理
14. Stage 1：冻结 LLM 与视觉编码器，只训练区域 projector，700K caption 数据，1 epoch，lr $1\times10^{-3}$。
15. Stage 2：训练 projector + LLM，视觉编码器冻结，1.7M 指令数据，1 epoch，lr $1\times10^{-5}$。
16. Stage 3：替换为二分类头，sigmoid focal loss，IoU>0.5 为正，加入 3 个硬负类名，3.9M 检测/REC 数据，1 epoch，lr $1\times10^{-5}$。
17. 推理：WeDetect-Base-Uni 取 top-100 候选 → RoIAlign + projector → object tokens → LLM 一次前向 → 二分类分数。
18. 多查询：每个查询单独前向，再合并结果；COCO 80 类需 80 次。

### 评测阶段
19. 零样本检测：LVIS minival/val、COCO、COCO-O、ODinW13/35；指标 AP / F1@IoU（LVIS 固定 AP）。
20. 候选召回：COCO/LVIS/PACO-LVIS，100/300 候选，AR50/AR。
21. 物体检索：COCO/LVIS，按类计算 P/R/F1，再跨类平均。
22. REC：RefCOCO/+/g、HumanRef；Top-1 accuracy、HumanRef 的 P/R/DF1/拒绝率。
23. LMM 检测：COCO、ODinW13；D³ 语言式检测。
24. 消融：多粒度标签、分阶段训练、损失函数、负检测数据、object token 数、proposal 顺序。
25. 速度：FPS 在 COCO 上测；Ref 的 FPS 在 RefCOCO 上测。

## 个人评价

**核心价值**: WeDetect 把“开放词汇检测”从“每来一个新查询就做一次跨模态融合”改成“**一次编码、多次检索**”。这不只是工程提速：它让视觉特征成为可复用的资产，从而派生出 WeDetect-Uni 的候选生成与历史数据物体检索。对需要处理上千类、海量图像库的遥感/监控场景，这种“离线建库 + 在线文本查询”的范式比逐查询融合更现实。

**可借鉴点**:
- **无融合 + 强数据 + 分阶段训练**可以超过融合模型。对遥感开放词汇检测，若融合层成为部署瓶颈，可优先考虑双塔 + 高质量领域数据，而不是继续堆融合模块。
- **数据引擎**值得迁移：objectness 检测器保证召回，SAM 提供边界，MLLM 生成层级标签与拒识。遥感中可把“粗类→细类→实例描述”换成“一级地物→二级地物→具体实例/属性”，并用高程/多光谱辅助。
- **多粒度标签采样**是一种低成本增广：同一框在不同迭代用不同粒度文本监督，既增加文本多样性，也构造动态负样本。
- **WeDetect-Uni 的“冻结检测器 + 单 prompt”**说明强判别特征可以极低成本转成通用候选生成器；适合做遥感图像库的离线索引。
- **WeDetect-Ref 的“候选 + 二分类”**避免了 LMM 坐标生成的 brittle 问题；在遥感指代任务中，可把候选框换成领域检测器输出，LLM 只做区域分类，显著降延迟。
- **中文类名模型**是重要 deployment 细节：如果直接拿英文类名复现，效果可能低于论文；多语言/跨域部署需重新生成类名 embedding。

**实验设计亮点**:
- 同时报告 LVIS minival/val、COCO、COCO-O、ODinW13/35、RefCOCO/+/g、HumanRef、D³，覆盖检测、候选、检索、REC、语言式检测，评估面很广。
- 速度与精度并列报告，且直接对比 Grounding-DINO 的 6×/3× 加速，突出无融合的实际价值。
- 消融覆盖数据标签、训练阶段、损失、负样本、token 数、顺序，每个结论都有具体 AP 支撑。
- 诚实报告 WeDetect-Ref 一次只能一个查询的局限，并解释为何仍比串行 LMM 快。

## 疑问解答 (Q&A)

### Q1: 为什么“无融合”会更快？只是少了几层网络吗？

**答**：不只是少几层。融合模型的视觉特征会与文本查询交互，因此**每个新查询都要重新做一次跨模态前向**；Grounding-DINO 在 LVIS 1203 类、chunk 40 下需要 31 次前向。WeDetect 的双塔中，图像特征与类名 embedding 都可预计算，分类只是一次点积；新增查询只增加文本编码与点积，视觉计算完全复用。因此速度优势随类别数/查询数放大。

### Q2: WeDetect-Uni 为什么冻结检测器、只学一个 prompt 就能生成高质量候选？

**答**：WeDetect 在开放词汇检测训练中已经学到强判别力的区域特征；冻结后，候选框对应的 box embedding 仍保留类别信息。此时只需在特征上做一次 linear probing，学一个“是否有物体”的通用 prompt，就能给所有候选打分。由于没有破坏原特征，top 候选的 embedding 仍可用于后续类别检索，这也是 object retrieval 能成立的前提。

### Q3: Object retrieval 与 CLIP 的图像检索有什么不同？

**答**：CLIP 把整张图压成一个全局 embedding，擅长“这张图整体是什么”；WeDetect-Uni 用**一组候选框 embedding**表示图像，擅长“图里有没有某个小物体”。因此 object retrieval 能检索烟头、部件等局部目标，而 CLIP 容易把背景/全局语义混入。Table 4 中 WeDetect-Large-Uni F1 83.6，CLIP 46.4，差距正来自局部表示。

### Q4: WeDetect-Ref 为什么不直接让 LLM 输出框坐标？

**答**：LLM 用交叉熵训练，数字被拆成离散 token，对精确坐标不敏感；多目标时还要串行生成大量 token，延迟高。WeDetect-Ref 改为：外部检测器给候选框，LLM 只判断“这个候选是否匹配查询”，用二分类头一次前向并行打分。这样既避免坐标回归缺陷，也避免 next-token 串行解码。

### Q5: WeDetect-Ref 的 13 倍加速是怎么算的？多查询时还有优势吗？

**答**：论文在 REC 设置下比较，WeDetect-Ref 4B 为 5.3 FPS，Qwen3-VL 4B 为 0.4 FPS，约 13 倍。WeDetect-Ref 一次前向只能处理一个查询，多查询要多次前向；但每次前向只做候选二分类，成本远低于生成式 LMM 的串行解码。论文指出即使多查询，仍可能比 Qwen3-VL 更快且更准（Table 2、Table 5）。

### Q6: 多粒度标签具体带来什么？消融如何解释？

**答**：每个对象有“粗类 / 细类 / 实例描述”多个标签，训练时随机采样一个。粗标签提供大类监督，细标签提供细粒度区分，实例描述提供更丰富的语言上下文；同时每轮 batch 的动态词表构造了多样负样本。Table 6 显示：去掉细粒度标签掉 2.2 AP，去掉粗粒度标签掉 0.9 AP，二者同时使用最好。

### Q7: 论文与代码有哪些不一致或未披露的信息？

**答**：至少有三点需要在复现时注意：
1. **中文类名**：论文正文未说明类别名语言，但官方 `README.md` 明确 WeDetect 是中文模型，示例为 `--text '鞋,床'`；仓库同时提供 `coco_zh_class_texts.json`、`lvis_v1_zh_class_texts.json`。用英文类名复现可能低于论文。
2. **256 个 prompt**：`config/wedetect_uni_base_finetune.py` 注释写明“mistakenly used 256 prompts, but actually only the first one is used”；论文描述的是“一个 objectness prompt”，有效行为一致，但配置保留了 256 个槽位。
3. **数据与标注器未开源**：15M 自标注数据、Qwen2.5-VL 标注器权重未随仓库发布；论文也未给出完整数据配比，复现精度受数据限制。
4. **后续扩展**：代码库 2026-06 的 WeDetect-Anything 不在本论文 v1 范围内，不应混入本笔记结论。

### Q8: 论文声称“15 个 benchmark SOTA”，具体包括哪些？

**答**：主要包括 LVIS minival/val、COCO、COCO-O、ODinW13/35、RefCOCO/+/g、HumanRef、D³，以及候选召回 COCO/LVIS/PACO-LVIS、物体检索 COCO/LVIS 等。不同表格的指标口径不同（AP、F1@IoU、AR、Top-1、PQ 等），不能跨表直接比较。
