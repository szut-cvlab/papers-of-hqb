## 摘要

**问题**: 基于 MLLM 的检测器把视觉-语言定位建模为自回归坐标生成。在密集场景中，全历史自回归（Full-History Auto-Regression, FHAR）会陷入**框重复循环（box repetition loop）**：模型反复输出相同或相近的框，直到解码预算耗尽，导致召回饱和、延迟累积。

**方案**: 提出 **Compressed Window Auto-Regression（WinAR，压缩窗口自回归）**。把长答案序列切分为连续生成窗口：
- 当前窗口内保留**精确的 token 级自回归**；
- 每个已完成窗口由 **Window History Compressor** 压缩为固定数量的潜在 token；
- 后续窗口只条件于“多模态前缀 + 压缩历史 + 当前窗口局部历史”。

**关键创新/贡献**：
- **创新点1（失败模式诊断）**: 把框重复循环归因于**历史答案注意力劫持**：不断增长的答案历史中重复坐标吸引过多注意力，挤占 system token 的 attention sink，模型越来越偏向已生成位置。
- **创新点2（WinAR）**: “紧凑记忆、局部生成”；减少原始历史坐标暴露，但保留跨窗口依赖。
- **创新点3（Window History Compressor）**: 保留窗口两端 B 个精确边界 token，中间 token 均分为 N 个区间做平均池化初始化 query，再经 cross-attention/FFN 压缩为 N 个 latent token。
- **创新点4（通用性）**: 可接入 RexOmni（NTP）与 LocateAnything（PBD/Hybrid），也支持多边形输出；显著降低训练显存，提高有效吞吐。

**验证**:
- RSDense（712 图，平均 412 目标/图）：RexOmni-WinAR 把 F1@0.5 从 **32.16** 提到 **39.36**，召回从 **36.82** 提到 **45.23**，重复率从 **35.48%** 降到 **13.00%**（Table 1）。
- LocateAnything-PBD：RSDense F1 **26.15→27.54**，重复率 **14.89%→2.13%**（Table 1）。
- 多边形检测：DOTA2 F1 **47.25→48.93**，SODA-A F1 **38.64→44.00**（Table 3）。
- 训练显存：RexOmni **57.62→42.97 GB**（-25.4%），LocateAnything **67.38→44.43 GB**（-34.1%）（Table 2）。
- 有效吞吐：RexOmni Valid Boxes/s **3.57→5.40**（Table 2）。

## 1. 引言

**背景 & 动机**:
- RexOmni、LocateAnything 等 MLLM 检测器把检测建模为自回归坐标生成，能处理复杂语言指令，超越固定接口的传统检测器。
- 但把这种范式扩展到密集场景（数百到数千目标/图）时，出现**长程 grounding** 问题：模型必须在有限解码预算内不断发现新目标，同时记住已定位目标。
- 作者观察到：密集配置下，FHAR 训练的 RexOmni 初期还能输出有效框，随后退化为**框重复循环**——相同/近乎相同的框反复输出，直到预算耗尽。
- 定量：前 400 个框预测中，冗余率从约 10% 升到接近 100%，新目标发现率从约 16% 降到接近 0。

**注意力分析**:
- 把条件上下文分为 system、visual、prompt、historical-answer 四个区域，跟踪坐标 token query 的 softmax 注意力质量。
- FHAR 下，历史答案注意力随解码 horizon 稳定增长，在重复循环开始时急剧上升，同时 system token 注意力显著下降。
- 先前研究指出初始 system token 常充当 attention sink，吸收多余注意力；密集 grounding 中，不断膨胀的原始答案历史用重复坐标模式**取代了 sink 分配**。
- 一旦原始坐标主导上下文，解码器偏向已生成位置；重复框又被追加回历史，形成**自增强循环**。

**本文思路**:
- 不保留全部原始历史坐标，而是**当前窗口精确、历史窗口压缩**。
- 用固定数量 latent token 表示每个已完成窗口，保留跨窗口依赖，但减少重复坐标的直接暴露。
- 这样既缓解注意力劫持，又把解码预算留给新目标发现。

**贡献**:
1. 识别 MLLM 检测器的长程失败模式：历史答案注意力劫持 → 框重复循环。
2. 提出 WinAR：窗口内精确自回归、窗口间压缩记忆，兼顾局部精确性与长程依赖。
3. 在场景密度、解码策略（NTP/PBD/Hybrid）、输出格式（框/多边形）上验证：提高精度、降低冗余、降低训练显存。

## 2. 相关工作

### 2.1 回归式目标检测

- Faster R-CNN、Cascade R-CNN、DETR、Deformable DETR、YOLO 等基于“分类 + 回归”的判别式范式。
- 通常用 backbone + FPN 提取多尺度特征，用 anchor/point/learnable query 实例化候选，再经标签分配、分类损失、回归损失优化。
- CLIP 之后的开放词汇检测器（Grounding DINO 等）用区域-文本对齐扩展到任意类别，但语言理解受轻量文本编码器与短类别名监督限制，难以处理复杂指令/推理。

### 2.2 基于 MLLM 的目标检测

- InternVL、InternVL3、SEED1.5、Qwen3-VL 等 MLLM 用共享生成目标统一异构视觉-语言任务。
- Pix2Seq 早期把类别与框坐标量化成离散 token，将检测变为自回归序列预测；RexOmni 用特殊坐标 token + 大规模 SFT + 几何感知 GRPO；LocateAnything 用 PBD 把框作为原子块并行解码。
- 这些工作仍保留**不断增长的原始答案历史**，没有显式解决长程密集 grounding 中坐标 token 主导后续预测的问题。
- WinAR 的区别：不改坐标表示/解码器，而是改**历史上下文如何跨窗口传递**。

## 3. 方法

### 3.1 预备知识

**MLLM 检测器**:
- 输入图像 $I$ 与自然语言 prompt $P$；视觉编码器得到视觉 token $\mathbf{V}$，system/prompt 映射为文本 embedding。
- 多模态前缀：

$$
\mathbf{X}=[\mathbf{S};\mathbf{V};\mathbf{P}].
$$

**全历史自回归（FHAR）**:

$$
p_{\theta}(\mathbf{Y}\mid\mathbf{X})
=
\prod_{t=1}^{T}
p_{\theta}\left(y_t\mid\mathbf{X},\mathbf{Y}_{<t}\right),
$$

其中 $\mathbf{Y}_{<t}$ 是所有已生成答案 token。

**坐标表示**:
- 水平/垂直像素坐标分别按图像宽/高归一化，均匀量化到 **1000** 个 bin；词表最后 1000 项 $\langle0\rangle$–$\langle999\rangle$ 复用为坐标 token。
- 一个框 $[x_0,y_0,x_1,y_1]$ 用 4 个坐标 token。
- RexOmni 用 `<|object_ref_start|>`、`<|box_end|>` 等结构 token 把类别短语与框序列化为扁平序列，标准 NTP。
- LocateAnything 把答案组织为长度 6 的原子 block，块内并行、块间自回归。

### 3.2 Compressed Window Auto-Regression

**核心原则**: *remember compactly and generate locally*。

**窗口划分**:
给定答案 $\mathbf{Y}=(y_1,\dots,y_T)$ 与窗口长度 $L$，切成 $K=\lceil T/L\rceil$ 个连续窗口：

$$
\mathbf{Y}=[\mathbf{Y}^{(1)};\mathbf{Y}^{(2)};\dots;\mathbf{Y}^{(K)}],
$$

其中 $\mathbf{Y}^{(k)}$ 是第 $k$ 个窗口。

**历史压缩**:
在生成第 $k$ 个窗口前，每个已完成窗口由 Window History Compressor $\mathcal{C}_{\phi}$ 转成 latent token：

$$
\mathbf{H}^{(i)}=\mathcal{C}_{\phi}\left(\mathbf{Y}^{(i)}\right),\qquad i<k.
$$

**窗口化生成**:

$$
p_{\theta}(\mathbf{Y}^{(k)}\mid\mathbf{X})
=
\prod_{t=1}^{T_k}
p_{\theta}\left(y_t^{(k)}\mid
\mathbf{X},\mathbf{H}_{<k},\mathbf{Y}^{(k)}_{<t}\right),
$$

- 只有当前窗口的局部历史 $\mathbf{Y}^{(k)}_{<t}$ 显式可见；
- 原始多模态前缀 $\mathbf{X}$ 始终保留；
- 答案上下文只通过压缩 latent token 增长，不再累积原始坐标序列。

**Window History Compressor**:
1. **边界保留**：固定窗口可能在类别短语/几何结构中间切断，因此保留窗口两端各 $B$ 个 token 原样 passthrough；只压缩中间 $L_{\mathrm{mid}}=L-2B$ 个 token。
2. **内容感知 query 初始化**：把中间 token 均匀分成 $N$ 个连续区间，每段平均池化得到一个 query；比随机初始化更能保留局部摘要。
3. **位置信息**：给中间 token 加可学习 window-local 位置 embedding，再线性投影得到 cross-attention 的 key/value。
4. **压缩器主体**：N 个 query 经 stacked cross-attention + FFN 精炼；输出经两层线性 + GELU 投影。
5. **重组**：压缩后的 N 个 latent token 与 front/back 边界 token 拼接，窗口从 $L$ 缩短为 **$2B+N$** 个 token。

为保证均分，超参满足 $L-2B$ 能被 $N$ 整除。

**训练与推理**:
- **训练**：逐窗口处理 GT 答案；第 $k$ 步只对当前窗口算交叉熵，之前窗口只以 $\mathbf{H}_{<k}$ 出现；压缩后丢弃原始窗口，避免保留全序列激活，显著省显存。
- **推理**：先生成 $\mathbf{Y}^{(1)}$；完成后压缩为 $\mathbf{H}^{(1)}$ 并从显式上下文移除；下一窗口条件于原始前缀 + 累积 memory + 当前局部 token；重复直到 EOS 或预算耗尽。
- **窗口粒度**：
  - RexOmni：固定 **L=300 tokens**，B=6，N=8；
  - LocateAnything：按 **50 个 block（300 tokens）** 切窗，B=1 block（6 tokens），N=2 blocks（12 tokens）；
  - 多边形：L=400，B=8，N=12。

## 4. 实验

### 4.1 训练与评测设置

**训练**:
- RexOmni 所有变体：4 epoch，per-device batch 1，梯度累积 16；base lr $4\times10^{-5}$，vision tower lr $4\times10^{-6}$。
- RexOmni-WinAR 额外用 lr $4\times10^{-4}$ 训练 Window History Compressor；默认 L=300、B=6、N=8；polygon L=400、B=8、N=12。
- 为控制“窗口训练增加长样本曝光”的影响，构造 **FHAR\*** 基线：含 $T$ 个答案 token 的样本过采样约 $\lceil T/L\rceil$ 次，匹配 WinAR 的样本曝光与优化步数。
- LocateAnything 采用相同优化设置，构造对应 FHAR* 与 WinAR 变体；L=50 blocks、B=1 block、N=2 blocks。
- FHAR 实验在 8×H100 上跑；WinAR 实验在 8×A40（48GB）上跑。

**数据/评测**:
- **DOTA2 & SODA-A**：联合训练集训练，验证/测试并集评测；类别平均 R/P/F1@IoU 0.5。
- **RSDense**：从 DOTA2 & SODA-A 评测集选 **>200 目标/图** 的 712 张图，平均 **412** 目标/图，最大 2305；类别无关、逐图匹配后平均。
- **DOTA2-Poly / SODA-A-Poly**：旋转框，每个目标 8 个坐标 token，输出长度翻倍。
- **SKU110K**：密集货架商品。
- **COCO**：验证普通场景不被牺牲。
- **冗余指标**：

$$
R_{\mathrm{dup}}=\frac{N_{\mathrm{dup}}}{N_{\mathrm{pred}}},\qquad
R_{\mathrm{over}}=\frac{N_{\mathrm{pred}}-N_{\mathrm{gt}}}{N_{\mathrm{gt}}},
$$

逐图计算后平均，越低越好。

### 4.3 消融

**压缩配置（Table 4）**:

| L | B | N | DOTA2&SODA F1 | RSDense F1 | RSDense R_dup |
|---:|---:|---:|---:|---:|---:|
| **300** | **6** | **8** | **68.49** | **44.78** | 5.38% |
| 200 | 4 | 6 | 67.22 | 44.56 | 4.21% |
| 200 | 0 | 20 | 64.82 | 32.47 | **2.59%** |
| 100 | 2 | 4 | 67.04 | 43.71 | **0.89%** |

- 更频繁压缩（L 300→100）持续降低冗余（5.38%→0.89%），但 F1 从 44.78 降到 43.71：窗口太短，局部精确上下文不足。
- **边界保留很关键**：同样 L=200，B=0、N=20 相比 B=4、N=6，DOTA F1 67.22→64.82，RSDense 44.56→**32.47**；即使给更多 latent token，也补不回边界精确信息。
- 默认 (300,6,8) 取得最佳精度，同时仍显著抑制冗余。
- **口径提示**：Table 4 中 (300,6,8) 的 68.49/44.78 高于 Table 1 主结果的 67.97/39.36；原文未解释差异，可能来自消融训练设置/样本曝光不同。本笔记按各表原值分别引用，不强行统一。

**压缩器深度（Table 5）**:
- 4 层：DOTA F1 65.49、RSDense 37.73；
- **6 层：67.97 / 39.36，最佳**；
- 8 层：64.62 / 39.32，召回略升但精度/冗余变差。
- 6 层是容量与过拟合/变换损失的最佳折中。

## 5. 结论

**总结**:
- 识别 MLLM 检测器在密集场景的长程失败模式：FHAR 下历史答案注意力劫持 → 自增强框重复循环。
- 提出 WinAR：当前窗口精确自回归、历史窗口压缩为 latent token，兼顾局部精确性与跨窗口依赖。
- 在 RexOmni、LocateAnything（NTP/PBD/Hybrid）、多边形输出上一致提升精度、降低冗余、降低训练显存。
- 越密集的场景收益越大，说明“压缩历史”是长程 grounding 的实用范式。

**局限**（论文未单列，实验体现）:
- 原始推理吞吐不一定提升：窗口压缩与 KV cache 预填充有额外开销；优势主要在**有效吞吐**与训练显存。
- 需要调窗口长度 L、边界 B、latent 数 N；不同输出格式需不同窗口粒度。
- 窗口边界仍可能切断语义结构，需靠 B 个边界 token 缓解。
- 依赖强 MLLM 基座与大规模密集检测数据；在普通 COCO 上提升较小（F1 +0.56）。
- 未探索强化学习/自适应窗口；窗口长度固定。

## 本文涉及到的模型具体结构

| 模块 | 结构 | 说明 |
|---|---|---|
| 基座检测器 | RexOmni（NTP）或 LocateAnything（PBD/Hybrid） | 坐标 token 化 + 自回归/并行块解码 |
| 窗口划分 | 固定 L token（RexOmni）或 L 个 block（LocateAnything） | 当前窗口保留完整自回归 |
| Window History Compressor | 边界 passthrough + 区间池化 query + cross-attn/FFN | 每个完成窗口 → 2B+N 个 latent token |
| 历史表示 | $\mathbf{H}^{(i)}=\mathcal{C}_\phi(\mathbf{Y}^{(i)})$ | 替代原始坐标历史 |
| 生成条件 | 多模态前缀 X + 压缩历史 H_<k + 当前窗口局部历史 | 跨窗口依赖保留，重复坐标暴露减少 |
| 默认配置 | RexOmni L=300,B=6,N=8；Locate L=50 blocks,B=1,N=2；6 层压缩器 | 多边形 L=400,B=8,N=12 |

**关键设计**:
- 不是改坐标表示，而是改**历史如何传递**；可与 NTP/PBD/Hybrid 正交组合。
- 保留窗口两端精确 token，避免边界切断语义/几何结构。
- 压缩器用内容感知的区间池化初始化 query，而非随机 query。
- 训练时压缩后丢弃原始窗口，省显存；推理时压缩完成窗口，省上下文。

## 个人评价

**核心价值**: WinARDet 的价值在于**把“长程生成失败”当成上下文管理问题**，而不是坐标表示问题。它没有换检测头、没有换 tokenizer，只是把“不断增长的原始答案历史”换成“当前窗口 + 压缩记忆”，就同时改善了召回、冗余和训练显存。这对遥感密集小目标非常直接：RSDense 上 F1 +7.2、重复率 -22.5 个百分点，说明很多“模型检测不到”其实是“解码预算被重复框吃掉了”。

**可借鉴点**:
- **历史压缩是长序列检测的关键**：当目标数上百/上千，KV cache 里最占空间、最干扰注意力的是重复坐标；用少量 latent memory 替代，比单纯加长训练序列更有效。
- **边界 token 不能压**：消融显示 B=0 即使给 20 个 latent token，RSDense F1 也从 44.56 跌到 32.47；结构化输出的窗口边界必须保留精确上下文。
- **窗口长度是精度-冗余 trade-off**：L 越小冗余越低但局部上下文越少；遥感密集场景可先从 L=300/B=6/N=8 起调。
- **与解码策略正交**：NTP、PBD、Hybrid 都能接，说明这是“历史管理”层，不是某个模型的专属技巧。
- **训练显存收益**：压缩后丢弃原始窗口，可直接把 67GB 降到 44GB，对 48GB 卡很实用。
- **评测要报冗余**：只看 F1/召回会掩盖“重复框耗尽预算”的问题；R_dup/R_over + Valid Boxes/s 更能反映实际可用性。

**实验设计亮点**:
- 先做注意力分析定位失败机制，再提出方法，因果链完整。
- FHAR* 曝光匹配基线很关键，排除了“WinAR 只是训练更久”的解释。
- 覆盖 NTP/PBD/Hybrid、框/多边形、遥感/货架/COCO，泛化证据强。
- 同时报精度、冗余、有效吞吐、训练显存，工程价值清晰。
- 附录全预测评测，避免 top-K 截断美化结果。

## 疑问解答 (Q&A)

### Q1: 框重复循环是怎么形成的？为什么叫“注意力劫持”？

**答**：FHAR 下，答案历史不断增长，里面包含大量重复坐标 token。坐标 token query 的注意力越来越多地分配到 historical-answer 区域，挤占了原本由 system token 充当的 attention sink。模型因此越来越偏向已生成的位置，输出重复框；重复框又追加回历史，进一步强化这个偏差，形成自增强循环。作者用四区域注意力质量曲线验证了这一点。

### Q2: WinAR 与“滑动窗口/截断历史”有什么区别？

**答**：简单截断会丢掉跨窗口依赖；WinAR 不丢，而是把每个完成窗口压缩成固定数量 latent token，后续窗口仍能条件于压缩历史。当前窗口内保留完整 token 级自回归，局部精确性不损失。它不是“只看最近 L 个 token”，而是“最近窗口精确 + 更早窗口压缩记忆”。

### Q3: Window History Compressor 具体怎么压缩？

**答**：
1. 保留窗口两端各 B 个 token 原样输出；
2. 中间 L-2B 个 token 均分为 N 段，每段平均池化得到一个 query；
3. 中间 token 加 window-local 位置 embedding，线性投影为 K/V；
4. N 个 query 经 stacked cross-attention + FFN 精炼；
5. 输出投影后与 front/back token 拼接，窗口变为 2B+N 个 token。
这样既有内容感知的 query 初始化，又保留边界精确信息。

### Q4: 为什么 B=0 时性能下降那么大？

**答**：固定窗口会切断类别短语或几何结构；没有边界 token，压缩器只能把被切断的碎片压进 latent，后续窗口拿不到精确的边界上下文。Table 4 中 L=200、B=0、N=20 相比 B=4、N=6，RSDense F1 从 44.56 跌到 32.47，说明“多给 latent token”不能替代“保留精确边界”。

### Q5: WinAR 能提速吗？为什么原始吞吐有时反而下降？

**答**：原始 Boxes/s 不一定提升，因为窗口边界要压缩历史、预填充 KV cache，有额外开销；LocateAnything PBD 的原始吞吐从 29.03 降到 26.15。但 WinAR 大幅减少重复框，**有效吞吐**（Valid Boxes/s）提升：RexOmni 3.57→5.40，Locate PBD 24.63→25.61。对实际应用，去掉冗余框后的有效产出更重要。

### Q6: 为什么训练显存能降这么多？

**答**：训练时逐窗口处理，已完成窗口压缩后，原始 token 表示和对应激活可以丢弃，不需要保留全序列激活。RexOmni 峰值从 57.62GB 降到 42.97GB（-25.4%），LocateAnything 从 67.38GB 降到 44.43GB（-34.1%），使 48GB A40 可训练。

### Q7: WinAR 对普通场景（COCO）有副作用吗？

**答**：基本没有。全预测评测 COCO F1 65.48→66.04，略升；主表 COCO 未单独列，但附录说明普通密度场景不退化。收益主要在密集场景，因为那里重复循环最严重；普通场景历史较短，压缩收益小，但也没有明显损害。

### Q8: 主要局限是什么？

**答**：
1. 原始推理吞吐不一定提升，压缩/KV 预填充有开销；
2. 需要调 L/B/N，且不同输出格式（框/多边形/块）要不同窗口粒度；
3. 窗口边界仍可能切断语义，需要 B 个边界 token 兜底；
4. 依赖强 MLLM 基座与密集数据；COCO 等普通场景收益有限；
5. 未探索自适应窗口/强化学习，窗口长度固定。
