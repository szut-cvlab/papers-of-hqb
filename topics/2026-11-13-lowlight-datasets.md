# 低光场景数据集调研报告

> 面向"低光场景小目标检测"，逐数据集核实 **图片规模 / 图像形式 / 目标尺度 / 单多目标 / 类别 / 分辨率 / 模糊程度**。  
> 数据来源：服务器 `10.18.32.108` 的 `/data1/datasets/hqb/` 目录（已清洗后实际状态），核实时间 2026-11-13。

---

## 一、核心结论：已收集三类低光数据集

围绕"低光场景小目标检测"课题，目前在服务器 `/data1/datasets/hqb/` 已收集并整理好 **9 个低光数据集**，按拍摄视角分为三大类：

**① 监控图片（5 个）** —— 最贴近"夜间视频侦查"部署场景，是本课题的主战场：

- **NightSurveillance**：监控俯视 + 夜间 + 行人，唯一"监控+夜间+有框"主基准（去重后 train 17,309 / test 17,298）；
- **LLVIP**：监控平视 + 夜间 （清洗后 train 5,714 / test 3,190）；
- **DETRAC**：监控路口 + 交通车辆多类（清洗后剩 test 5,660）；
- **IntersectionFlow5K**：高密度路口监控，8 类交通目标，小目标极密集（服务器子集 1,324 张）；
- **FishEye8K**：鱼眼镜头监控，5 类，含夜间/早晨/黄昏时段（3,090 张）。

**② 车载夜景图片（3 个）** —— 小目标占比最高，但视角是车载前视，与监控有域差异：

- **ACDC（night）**：车载前视 + 夜间，同场景有白天对照图（train 400 / val 106）；
- **NightCity**：车载前视 + 夜间，分割标注转检测框（train 2,998 / val 1,299）；
- **BDD100K（night）**：车载前视 + 夜间，10 类、规模最大（train 27,888 / val 3,906）。

**③ 近景图片（1 个）** —— 相机手持拍摄，大目标为主：

- **NOD**：DSLR 近景拍摄，3 类，高分辨率（服务器子集 564 张）。

> **一句话总结**：监控类提供"部署场景 + 行人 + 配对"（但目标偏大），车载类提供"小目标 + 多类"（但视角不同），近景类提供"跨域泛化对照"（大目标）。三类互补，共同支撑低光小目标检测研究。

## 五、关键结论与建议

1. **"小目标"和"监控"在原有数据里是错位的**：监控数据集（NightSurveillance/LLVIP/DETRAC）目标都偏大，小目标反而集中在车载数据集（NightCity/BDD100K/ACDC）。但新增的 **IntersectionFlow5K 和 FishEye8K 补上了"监控 + 小目标"这一缺口**——两者都是监控视角且小目标占比 60%+，是监控小目标检测的更好候选。
2. **五个监控数据集完成/未完成清洗的遗留问题**：NightSurveillance 需自行重划验证集（时序泄漏）；LLVIP 缺红外目录；DETRAC 删空 train 后需重划；IntersectionFlow5K 和 FishEye8K 是 pyc 同学的、未转 COCO（仍是 YOLO 格式）。
3. **车载三件套（BDD100K/NightCity/ACDC）小目标占比极高**，是做"小目标检测"的主要数据来源，但视角是车载前视，与监控俯视有域差异。
4. **NOD 是近景大目标**，仅作跨域泛化测试集。
5. **类别统一**：若要合并训练，需把各数据集映射到统一类别表（person/car 等），非目标类别的框删除（详见之前讨论）。

## 七、怎么生成低光图像

### 7.1 方法总览

| # | 方法                                       | 代表工作                                                                                                              | 真实性   | 成本 | 推荐度   |
| - | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----- | -- | ----- |
| ① | 逆 ISP + RAW 域物理噪声注入                      | Brooks 2019；BMVC 2021 *Crafting Object Detection in Very Low Light*；IJCV 2023 *Instance Segmentation in the Dark* | ★★★★★ | 中  | 主线    |
| ② | 全 ISP 仿真（多相机 + 200 条 tone curve + 白平衡扰动） | *Enhancing Low-Light Images: A Synthetic Data Perspective*                                                        | ★★★★☆ | 中高 | 预训练   |
| ③ | sRGB 光照衰减 + 统计对齐                         | Dark-traffic                                                                                                      | ★★☆☆☆ | 极低 | 只做消融  |
| ④ | 3D 渲染内嵌退化                                | SpaceDG                                                                                                           | ★★★★★ | 高  | 不适用检测 |
| ⑤ | GAN 日到夜迁移                                | CycleGAN 类                                                                                                        | ★★★☆☆ | 中  | 慎用    |

### 7.2 主线四步

```
正常光 sRGB X
  → ① Unprocessing（逆 tone mapping → 逆 gamma → 逆色彩矩阵 → 逆白平衡 → 重插 Bayer）
  → ② 曝光衰减 I_dark = I_raw × k，k ∈ [0.01, 0.1]
  → ③ 噪声注入 Poisson(散粒) + Tukey(读出) + 条带 + 量化
  → ④ 前向 ISP（可随机化白平衡/色彩矩阵/色调曲线）
  → 低光 sRGB X_dark（标注与 X 完全一致）
```

**为什么这条最适合**：标注零成本、天然配对（可直接喂对比学习的三元组损失）、曝光系数可扫（构造轻度到极暗的梯度）、已在检测/分割任务上验证过。

### 7.3 已知问题

- 网络图 ISP 未知不可精确反演，粗糙近似即可（论文明确说不需要恢复原始 RAW）；
- 强 JPEG 压缩的底图，逆 ISP 会把压缩块当内容放大；
- 每台"虚拟相机"要单独标定噪声参数，否则跨数据集的暗图噪声分布不一致。

### 7.4 用真实配对校验合成质量（这一步别省）

拿 DARK FACE 的 789 组真实配对，对合成出的暗图做三件事：

1. 亮度直方图对比（合成是否过亮或过暗）；
2. 噪声统计对比（暗部方差随亮度的变化曲线）；
3. 下游掉点幅度对比（同一检测器在"真实暗图"与"合成暗图"上的 mAP 差距）。

差距过大说明噪声模型不准，回到第 ③ 步调参。ACDC 的同场景正常光/夜图对也可做粗校验。
